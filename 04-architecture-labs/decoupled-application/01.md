# Decoupled Application  SQS and Lambda Lab

## 1. Purpose

This lab demonstrates the basic idea of a decoupled application using Amazon SQS and AWS Lambda.

The goal is to separate the producer from the consumer so that the producer does not need to directly invoke or wait for the consumer.

The architecture built in this lab is:

```
Producer
   |
   v
 SQS Queue
   |
   v
Lambda
   |
   v
Processing
```

## 2. Services Used

- Amazon SQS
- AWS Lambda
- AWS IAM
- AWS CloudWatch Logs
- AWS CLI

The lab was built locally using Floci.

## 3. Architecture

```
                         Decoupled Application

                              Producer
                                 |
                                 | SendMessage
                                 v
                         +---------------+
                         |      SQS      |
                         |    my-pipe    |
                         +-------+-------+
                                 |
                                 | Event Source Mapping
                                 v
                         +---------------+
                         |    Lambda     |
                         | sqs-consumer  |
                         +-------+-------+
                                 |
                                 v
                             Processing
```

- The producer sends messages to SQS instead of directly calling Lambda.
- SQS acts as a buffer between the producer and consumer.
- Lambda consumes messages from SQS through an Event Source Mapping.

## 4. Step 1  Create the SQS Queue

A queue named `my-pipe` was used.

Queue URL:

```
http://localhost:4566/000000000000/my-pipe
```

Messages were sent using AWS CLI:

```
aws sqs send-message \
  --queue-url http://localhost:4566/000000000000/my-pipe \
  --message-body "hello"
```

Another example:

```
aws sqs send-message \
  --queue-url http://localhost:4566/000000000000/my-pipe \
  --message-body "hello from SQS"
```

The command returned a `MessageId`, confirming that the message was accepted by SQS.

## 5. Step 2  Receive Messages from SQS

Before Lambda was connected, the queue was tested manually using:

```
aws sqs receive-message \
  --queue-url http://localhost:4566/000000000000/my-pipe \
  --max-number-of-messages 10 \
  --wait-time-seconds 20
```

The response contained messages such as:

```json
{
  "MessageId": "...",
  "ReceiptHandle": "...",
  "Body": "hello"
}
```

This demonstrated that messages were successfully stored in the SQS queue.

Important concept:

```
ReceiveMessage != DeleteMessage
```

Receiving a message does not mean that it has been permanently deleted.

## 6. Step 3  Create the Lambda Function

A Lambda function named `sqs-consumer` was created.

The Lambda handler was:

```python
def lambda_handler(event, context):
    for record in event["Records"]:
        message = record["body"]
        print(message)
```

The function expects an event containing SQS records.

For example:

```json
{
  "Records": [
    {
      "body": "Hello from SQS"
    }
  ]
}
```

The Lambda extracts the message using:

```
record["body"]
```

## 7. Step 4  Package the Lambda

The Lambda source file was packaged into a ZIP file.

The structure was:

```
function.zip
└── lambda_function.py
```

The ZIP file was created with:

```
zip function.zip lambda_function.py
```

The contents were checked with:

```
unzip -l function.zip
```

The Python file must be located at the root of the ZIP archive.

## 8. Step 5  Create the IAM Role

Lambda requires an execution role.

A trust policy was created in `trust-policy.json`.

The trust policy allows Lambda to assume the role:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "lambda.amazonaws.com"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
```

The role was created with:

```
aws iam create-role \
  --role-name lambda-role \
  --assume-role-policy-document file://trust-policy.json
```

Important distinction:

- **Trust Policy** defines who can assume this role. In this case, Lambda.
- **Permissions Policy** defines what the role can do.

These are separate concepts.

## 9. Step 6  Create the Lambda Function

The Lambda function was created from the ZIP package:

```
aws lambda create-function \
  --function-name sqs-consumer \
  --runtime python3.12 \
  --role arn:aws:iam::000000000000:role/lambda-role \
  --handler lambda_function.lambda_handler \
  --zip-file fileb://function.zip
```

The Lambda function was then available as `sqs-consumer`.

## 10. Step 7  Test the Lambda

The Lambda was first tested independently from SQS.

The test payload simulated an SQS event:

```
aws lambda invoke \
  --function-name sqs-consumer \
  --cli-binary-format raw-in-base64-out \
  --payload '{"Records":[{"body":"Hello from SQS"}]}' \
  output.json
```

The invocation returned:

```json
{
  "StatusCode": 200,
  "ExecutedVersion": "$LATEST"
}
```

This confirmed that the Lambda could successfully process the expected event structure.

## 11. Step 8  Get the SQS Queue ARN

Lambda Event Source Mapping requires the SQS queue ARN.

The ARN was retrieved with:

```
aws sqs get-queue-attributes \
  --queue-url http://localhost:4566/000000000000/my-pipe \
  --attribute-names QueueArn
```

The queue ARN was:

```
arn:aws:sqs:us-east-1:000000000000:my-pipe
```

## 12. Step 9  Create the Event Source Mapping

The SQS queue was connected to Lambda using:

```
aws lambda create-event-source-mapping \
  --function-name sqs-consumer \
  --event-source-arn arn:aws:sqs:us-east-1:000000000000:my-pipe
```

The resulting configuration showed:

```json
{
  "BatchSize": 10,
  "EventSourceArn": "arn:aws:sqs:us-east-1:000000000000:my-pipe",
  "FunctionArn": "arn:aws:lambda:us-east-1:000000000000:function:sqs-consumer",
  "State": "Enabled"
}
```

The important value was `State: Enabled`. This means the Event Source Mapping was active.

## 13. Step 10  Test SQS to Lambda

A new message was sent to SQS:

```
aws sqs send-message \
  --queue-url http://localhost:4566/000000000000/my-pipe \
  --message-body "Hello from my decoupled application"
```

The queue was then checked:

```
aws sqs get-queue-attributes \
  --queue-url http://localhost:4566/000000000000/my-pipe \
  --attribute-names ApproximateNumberOfMessages
```

The result was:

```json
{
  "Attributes": {
    "ApproximateNumberOfMessages": "0"
  }
}
```

The Event Source Mapping was also verified:

```
aws lambda get-event-source-mapping \
  --uuid 7a2b5404-e790-4b64-8344-23586bc29aef
```

It returned `State: Enabled`. This demonstrated that the SQS to Lambda integration was active and the queued message was consumed.

## 14. What Was Learned

This lab demonstrated several important AWS concepts.

**SQS as a decoupling layer**

The producer does not need to directly communicate with the consumer.

Instead:

```
Producer -> SQS -> Consumer
```

**Lambda as a consumer**

Lambda can process messages coming from SQS.

```
SQS -> Lambda
```

**Event Source Mapping**

Event Source Mapping connects the SQS queue to Lambda and allows Lambda to consume messages from the queue.

**IAM Role**

Lambda requires an execution role. The role has:

- **Trust Policy** -> Who can assume the role?
- **Permissions Policy** -> What can the role do?

**Testing**

The Lambda was tested independently before connecting it to SQS. This helped separate:

- the Lambda problem
- from the SQS to Lambda integration problem

## 15. Current Architecture

At the end of the lab, the architecture was:

```
                  Producer
                     |
                     | SendMessage
                     v
              +-------------+
              |     SQS     |
              |   my-pipe   |
              +------+------+
                     |
                     | Event Source Mapping
                     v
              +-------------+
              |   Lambda    |
              | sqs-consumer|
              +-------------+
                     |
                     v
                 Processing
```

The producer and consumer are no longer directly coupled. The SQS queue provides a buffer between them.
