# S3 — Simple Storage Service

## What it is

S3 is AWS's object storage service. Stores data as **objects** in **buckets** — no file system, no hierarchy. Data is stored redundantly across multiple AZs, accessible over HTTP/HTTPS. S3 is the backbone of virtually every AWS architecture — backups, static assets, data lakes, media, logs, and application state.

## Buckets & objects

- **Bucket names**: globally unique across all AWS accounts/regions. 3–63 chars, lowercase.
- **Object key**: full path (e.g. `images/profile.jpg`). Not a real folder — just part of the key name.
- **Object size**: up to **5 TB** per object. Single PUT handles up to **5 GB**; larger requires **Multipart Upload**.

## Storage classes

| Class | Use case | Retrieval |
|---|---|---|
| **S3 Standard** | Frequently accessed | Instant |
| **Intelligent-Tiering** | Unknown/varying access patterns; auto-moves between tiers | Instant |
| **Standard-IA** | Infrequently accessed, fast retrieval | Instant (per-GB fee) |
| **One Zone-IA** | Infrequent, can be recreated; single AZ | Instant |
| **Glacier Instant** | Archived, rarely accessed | Milliseconds |
| **Glacier Flexible** | Archive | Minutes to hours |
| **Glacier Deep Archive** | Long-term archive, lowest cost | 12–48 hours |

- Durability: 99.999999999% (11 nines) for most classes. Lower cost = slower retrieval.

## Lifecycle rules

- **Transition actions**: move objects to IA/Glacier after N days.
- **Expiration actions**: delete objects or old versions after set time.
- **Minimum ages**: 30 days before IA, 90 days before Glacier. Cannot transition on day 1.

## Encryption

| Type | How it works |
|---|---|
| **SSE-S3** | S3-managed AES-256. Zero config, simplest. |
| **SSE-KMS** | KMS key — audit key access, control rotation. |
| **SSE-C** | You provide keys; S3 uses and discards them. |
| **Client-side** | Encrypt before upload; S3 never sees plaintext. |

## Access control

- **IAM policies**: identity-based, control who/what.
- **Bucket policies**: resource-based, enable cross-account or public access.
- **Block Public Access**: account/bucket-level override — blocks even if policy allows public.

## Versioning

- Enables multiple versions of same object. Deleting creates a **delete marker** — data retained.
- Cannot be turned off once enabled (only suspended). MFA Delete for permanent version removal.

## Static website hosting

- Enable on bucket, provide index/error document. Bucket policy must allow public read.
- **HTTP only** on S3 website endpoint — use CloudFront + ACM for HTTPS.

## S3 ↔ EC2 & CloudFront

- **EC2**: AMIs stored in S3. EBS = block for single instance vs S3 = object shared everywhere.
- **CloudFront**: CDN fronting S3 for speed + HTTPS + DDoS. **OAC** restricts direct S3 access.
- **Events**: Put/Post/Copy/Delete → Lambda, SQS, SNS, or EventBridge.
- **Multipart Upload**: required above 5 GB, recommended above 100 MB. Parallel parts, resume on failure.

## Exam domains

- [x] **Secure (30%)** — encryption (SSE-S3/KMS/SSE-C), bucket policies, Block Public Access, OAC
- [x] **Resilient (26%)** — versioning, cross-region replication, 11-nines durability
- [x] **High-Performing (24%)** — storage class selection, multipart upload, Transfer Acceleration, CloudFront
- [x] **Cost-Optimized (20%)** — lifecycle rules, Intelligent-Tiering, versioning costs

## Key gotchas

1. **Bucket names globally unique** — never shared across accounts/regions
2. **Deleting versioned objects creates delete marker** — data billed until versions permanently deleted
3. **Lifecycle minimum ages**: 30 days for IA, 90 days for Glacier
4. **Glacier Deep Archive**: 12–48 hours retrieval — not for "fast" needs
5. **S3 website endpoint is HTTP only** — use CloudFront for HTTPS
6. **Block Public Access overrides bucket policies** — safety net
7. **Cross-account access requires bucket policies** — IAM alone won't work
8. **One Zone-IA is single AZ** — not 11-nines durability

## Related services

- **EC2** — AMIs stored in S3
- **CloudFront** — CDN fronting S3 for speed + HTTPS
- **Lambda** — triggered by S3 events
