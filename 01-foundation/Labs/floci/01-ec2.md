# Lab 01 — EC2 with Floci

> Launch an EC2 instance locally, inspect it, and clean up. No real charges — it's all emulated.

**Reference notes:** `services/EC2.md`

## 1. Create a key pair

```bash
aws ec2 create-key-pair --key-name lab-key --query 'KeyMaterial' --output text > lab-key.pem
chmod 400 lab-key.pem
```

**Verification:**

```bash
aws ec2 describe-key-pairs --key-names lab-key
```

## 2. Find an AMI

Floci ships with its own AMIs. List what's available:

```bash
aws ec2 describe-images --owners self
```

If empty, use the built-in one floci provides. You can also describe by filtering:

```bash
aws ec2 describe-images --filters "Name=architecture,Values=x86_64" --query 'Images[*].[ImageId,Name]'
```

## 3. Launch an instance

```bash
aws ec2 run-instances \
  --image-id ami-00000000 \
  --instance-type t2.micro \
  --key-name lab-key \
  --count 1
```

> If `ami-00000000` fails, grab an actual AMI ID from step 2 and substitute it. Floci accepts most IDs but checks well-formedness.

## 4. Inspect the instance lifecycle

```bash
aws ec2 describe-instances --filters "Name=tag:Name,Values=*" --query 'Reservations[*].Instances[*].{ID:InstanceId,State:State.Name,Type:InstanceType,AZ:Placement.AvailabilityZone}'

# Watch state
aws ec2 describe-instances --query 'Reservations[0].Instances[0].State'
```

## 5. Tag it (best practice)

```bash
INSTANCE_ID=$(aws ec2 describe-instances --query 'Reservations[0].Instances[0].InstanceId' --output text)
aws ec2 create-tags --resources $INSTANCE_ID --tags Key=Name,Value=lab-ec2

aws ec2 describe-instances --instance-ids $INSTANCE_ID --query 'Reservations[0].Instances[0].Tags'
```

## 6. Stop / Start cycles

```bash
# Stop (no compute charge in real AWS; EBS still billed)
aws ec2 stop-instances --instance-ids $INSTANCE_ID

# Start
aws ec2 start-instances --instance-ids $INSTANCE_ID
```

Note how the public IP (if any) is reassigned on start — the private IP stays stable.

## 7. Reboot

```bash
aws ec2 reboot-instances --instance-ids $INSTANCE_ID
```

## 8. Instance types

List what types floci emulates:

```bash
aws ec2 describe-instance-types --query 'InstanceTypes[*].[InstanceType,VCpuInfo.DefaultVCpus,MemoryInfo.SizeInMiB]' | head -30
```

## 9. User data (bootstrap script)

```bash
cat > userdata.sh <<'EOF'
#!/bin/bash
echo "bootstrapped $(date)" > /tmp/bootstrap.log
EOF

aws ec2 run-instances \
  --image-id ami-00000000 \
  --instance-type t2.micro \
  --user-data file://userdata.sh
```

**Note:** user data runs once on first boot (16 KB limit).

## Cleanup

```bash
aws ec2 terminate-instances --instance-ids $INSTANCE_ID
aws ec2 delete-key-pair --key-name lab-key
rm lab-key.pem
```

## Exam hooks

- SG stateful vs NACL stateless — done in [03-security-groups.md](03-security-groups.md) / [04-nacls.md](04-nacls.md)
- Auto-assigned public IP changes on stop/start → Elastic IP is stable → see lab 02/08
- Root volume deleted on terminate; non-root preserved → lab 05

## Gotchas to remember

1. SGs **stateful**, NACLs **stateless**
2. Deleting AMI doesn't delete snapshots
3. t-series CPU credits — burst then throttle
4. Hibernation requires encrypted root volume
5. Enable IMDSv2 to stop SSRF credential theft
